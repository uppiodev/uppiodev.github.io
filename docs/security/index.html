Security and isolation

Uppio is shared hosting on CloudLinux: many accounts on one server, each fenced off by the operating system rather than by a container or a virtual machine of its own. That keeps an account small and cheap; the price is a few things that accounts share, listed below.

How accounts are kept apart

  • A user of its own. Every account is a separate system user. Its apps, cron jobs and the commands your agent runs work as that user.
  • Its own view of the files. With CageFS an account sees a file system of its own: other accounts’ homes, files and processes are out of sight.
  • Its own limits. Every process of an account runs in its LVE, CloudLinux’s resource container: PHP, Python and Node apps, cron jobs and the commands your agent runs share the account’s CPU, memory, processes and disk IO. A busy or broken app slows down its own account, not the neighbours. The numbers of each plan are on Pricing; your agent sees them in get_account.
  • Only its own sites inside the server. Over the server’s local network an account reaches MariaDB, DNS and its own sites, nothing else of other accounts.

What accounts share

  • The kernel of the operating system. We keep it and the system updated.
  • The server’s IP addresses. Outgoing connections of every account come from them: if one account gets an address blocked somewhere, the others feel it too.
  • One MariaDB server. Each database has a user of its own with rights to that database alone, up to 40 connections at once, and its size counts towards the plan’s disk. Lock names (GET_LOCK) are shared by the whole server: begin yours with your database’s name.
  • The apps’ domain, madeyour.app. Any app on it can set a cookie for all of madeyour.app. Name your session cookie with the __Host- prefix (with Secure, Path=/ and no Domain): no other app can set or replace it. An own domain is yours alone.

Abuse

  • Accounts can not send mail straight from the server: port 25 is closed and there is no local mail. Mail goes through an email API or a provider’s SMTP on port 587 or 465.
  • The beta is by invite. Abuse is against the acceptable use policy; report it here, and we can suspend an account within minutes while we look into it.

Your API key

  • One key opens the whole account: apps, deploys, databases, variables and commands. Your agent keeps it outside the repository, in ~/.config/uppio/<project>.json with mode 600, and passes it to MCP clients through their settings, not through files you share.
  • An agent reads files, so a prompt injection could make it reveal the key. If you think it leaked, have the agent replace it, or get a new one by email: If the key leaks or is lost.
  • OAuth for MCP is coming: then the MCP client holds the token, not a file your agent reads.

Your data

  • The servers are in Germany. Plans with backups are backed up every night, encrypted, to separate storage in Germany.
